# What Exactly Is Kubernetes?

The official definition is something like:

> "Kubernetes is an open-source container orchestration platform."

That's correct,

but not very helpful.

A better definition is:

> **Kubernetes is an operating system for your containers.**

Just as your laptop's operating system manages:

- Processes
- Memory
- CPU
- Files
- Networking

Kubernetes manages:

- Containers
- Networking
- Storage
- Scaling
- Recovery
- Deployments
- Scheduling

Instead of managing one computer,

it manages an entire cluster of computers.

# Docker vs Kubernetes

Many beginners think:

> "If Kubernetes exists, why do we still need Docker?"

Because they solve different problems.

Docker answers:

> **How do I package an application?**

Kubernetes answers:

> **How do I run thousands of packaged applications reliably?**

Think of it like this:

```
Docker

↓

Creates Containers
```

```
Kubernetes

↓

Manages Containers
```

Without containers,

Kubernetes has nothing to manage.

# What Kubernetes Does Automatically

Imagine your application is deployed.

```
FastAPI

↓

Docker

↓

Kubernetes
```

Without Kubernetes, you manually:

- Start containers
- Stop containers
- Restart failures
- Scale containers
- Update versions
- Configure networking

With Kubernetes,

it continuously watches your application and automatically:

- Restarts failed containers
- Starts new containers when needed
- Removes unhealthy containers
- Balances traffic
- Performs rolling updates
- Rolls back failed deployments
- Distributes containers across machines

# High-Level Architecture

Imagine this cluster.

```text
                Kubernetes Cluster

        +---------------------------+
        |      Control Plane        |
        +---------------------------+
             │      │      │
             │      │      │
    ----------      │      ----------
   │                 │               │
+--------+      +--------+      +--------+
| Worker |      | Worker |      | Worker |
| Node 1 |      | Node 2 |      | Node 3 |
+--------+      +--------+      +--------+
   │                │               │
   │                │               │

```

We'll learn every box in later chapters.

For now,

remember:

- One cluster
- One control plane
- Multiple worker machines
- Applications run as Pods

| Object | Purpose |
|----------|----------|

# Key Takeaway

The biggest mindset shift in Kubernetes is this:

> **Docker packages applications. Kubernetes operates applications.**

Docker gives you a container.

Kubernetes makes sure that container is:

- Running
- Healthy
- Reachable
- Scalable
- Recoverable
- Updatable

As a backend engineer, you don't need to become a Kubernetes administrator, but you **do** need to understand how your
applications are deployed, managed, and operated in production. That understanding is exactly what this course aims to
build.
