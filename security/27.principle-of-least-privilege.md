# What is the Principle of Least Privilege?

The **Principle of Least Privilege (PoLP)** states:

> Every user, application, service, or process should have **only the minimum permissions required** to perform its job.

Nothing more.

Nothing less.

______________________________________________________________________

# Why is it Important?

Suppose an attacker compromises your application.

If the application has unlimited permissions,

the attacker also gains unlimited permissions.

If the application has limited permissions,

the damage is greatly reduced.

Least Privilege limits the **blast radius** of an attack.

______________________________________________________________________

# Simple Example

Imagine a librarian.

A librarian needs permission to:

- Add books
- Update books
- Issue books

Should they be allowed to:

- Delete the database?
- Create administrator accounts?
- Access payroll information?

No.

They should have only the permissions required for their job.

This is the Principle of Least Privilege.

# Backend Example

Bad Design

```text id="polp2701"
FastAPI

↓

Database Administrator
```

If the application is compromised,

the attacker can:

- Drop tables
- Delete databases
- Create new users
- Modify permissions

______________________________________________________________________

# Better Design

```text id="polp2702"
FastAPI

↓

Read

↓

Write

↓

Update

↓

No DROP DATABASE
```

Now,

even if the application is compromised,

critical database operations remain protected.

______________________________________________________________________

# Linux Example

Suppose your application stores uploaded files.

Does it need access to:

```text id="polp2703"
/etc/

/boot/

/root/
```

No.

It only needs access to

```text id="polp2704"
/app/uploads
```

Grant access only to the required directory.

______________________________________________________________________

# Docker Example

Bad

```dockerfile id="polp2705"
USER root
```

If attackers exploit your application,

they now have root access inside the container.

Better

```dockerfile id="polp2706"
RUN useradd appuser

USER appuser
```

Now,

the application runs with limited privileges.

______________________________________________________________________

# Cloud Example

Suppose your application runs on AWS.

Bad

```text id="polp2707"
IAM Role

↓

AdministratorAccess
```

The application can do everything.

Better

```text id="polp2708"
IAM Role

↓

Read S3 Bucket

↓

Write Logs

↓

Nothing Else
```

Only the required AWS services are accessible.

______________________________________________________________________

# API Example

Suppose your API has two roles.

```text id="polp2709"
Admin

↓

Delete Users

Create Users

Manage Roles
```

```text id="polp2710"
Customer

↓

View Profile

Update Profile

Place Orders
```

Customers should never receive administrator permissions.

# File System Example

Suppose your application generates reports.

Bad

```text id="polp2711"
Read

Write

Execute
```

Better

```text id="polp2712"
Read

Write
```

If execution isn't required,

don't grant it.

______________________________________________________________________

# Database Example

Suppose your application only reads data.

Bad

```text id="polp2713"
SELECT

INSERT

UPDATE

DELETE

DROP
```

Better

```text id="polp2714"
SELECT
```

Applications should receive only the permissions they actually use.

______________________________________________________________________

# Secrets Example

Bad

```text id="polp2715"
Application

↓

All Production Secrets
```

Better

```text id="polp2716"
Application

↓

JWT Secret

↓

Database Password
```

Only provide the secrets required by that service.

# Kubernetes Example (Conceptual)

Even though we're skipping Kubernetes,

Each Pod should receive:

- Minimal permissions

- Minimal secrets

# Least Privilege Isn't Just About Users

Apply it to:

- Users
- APIs
- Services
- Databases
- Containers
- Cloud resources
- File systems
- Secrets
- Networks

Everything should have only the permissions it needs.

# Benefits

Applying PoLP helps:

- Reduce attack surface
- Limit data exposure
- Reduce accidental mistakes
- Improve compliance
- Minimize the impact of compromised accounts

# Real Interview Scenario

**Question**

Suppose your FastAPI application only reads books from the database.

Should it connect using the database administrator account?

**Answer**

No.

The application should use a dedicated database account with only `SELECT` permission. If the application is
compromised, the attacker cannot modify or delete data because those permissions were never granted.

______________________________________________________________________

# Best Practices

✅ Create dedicated service accounts.

✅ Grant only required permissions.

✅ Run Docker containers as non-root.

✅ Use restricted IAM roles.

✅ Limit database permissions.

✅ Restrict filesystem access.

✅ Review permissions regularly.

______________________________________________________________________

# Common Mistakes

### Running Everything as Administrator

Administrator accounts should rarely be used by applications.

______________________________________________________________________

### Sharing One Database User

Different applications

should have different database accounts

with different permissions.

______________________________________________________________________

### Giving Full Cloud Permissions

Avoid broad roles like

```text id="polp2718"
AdministratorAccess
```

Create narrowly scoped roles instead.

______________________________________________________________________

### Forgetting Old Permissions

As applications evolve,

permissions often accumulate.

Regularly audit and remove unnecessary access.

______________________________________________________________________

# Quick Comparison

| Poor Practice | Better Practice |
| ------------------------ | ------------------------- |
| Run as root | Run as non-root |
| Database admin account | Dedicated limited account |
| Full AWS permissions | Minimal IAM role |
| Full filesystem access | Specific directories only |
| Share secrets everywhere | Only required secrets |

# Interview Deep Dive

## Answer

**Question:** What is the Principle of Least Privilege?

The Principle of Least Privilege states that every user, application, service, or process should receive only the
minimum permissions required to perform its task. This limits the impact of security breaches, reduces the attack
surface, and prevents accidental or malicious misuse of privileges. It applies to databases, APIs, Docker containers,
cloud services, file systems, and operating systems.
