# 1. What is a File System?

A file system is the method an operating system uses to organize, store, retrieve, and manage files on a storage device.

Without a file system, your SSD or HDD is simply a collection of bytes with no organization.

The file system answers questions such as:

- Where is a file stored?
- What is its name?
- Who owns it?
- What permissions does it have?
- When was it created or modified?
- How can it be accessed efficiently?

______________________________________________________________________

# 2. Why Do We Need a File System?

Imagine a library with thousands of books.

Without shelves, labels, or categories, finding a single book would be almost impossible.

A file system plays the same role for data.

It organizes everything into directories and files, making retrieval fast and reliable.

______________________________________________________________________

# 3. How Linux Stores Files

One of the most important Linux philosophies is:

> **Everything is a file.**

This includes:

- Regular files
- Directories
- Hard disks
- USB devices
- Keyboards
- Mice
- Printers
- Network interfaces
- Processes (through `/proc`)

This design gives Linux a simple and consistent interface.

______________________________________________________________________

# 4. Linux File System Hierarchy (FHS)

Unlike Windows, Linux does **not** have drives like:

```
C:\
D:\
E:\
```

Linux has a **single directory tree** that starts from the root directory.

```
/
├── bin
├── boot
├── dev
├── etc
├── home
├── lib
├── media
├── mnt
├── opt
├── proc
├── root
├── run
├── sbin
├── srv
├── sys
├── tmp
├── usr
└── var
```

Everything starts from `/`.

# 5. Understanding Important Directories

## /

The root directory.

Everything in Linux starts here.

Example:

```
/home
/etc
/usr
/var
```

______________________________________________________________________

## /home

Contains personal directories for normal users.

Example

```
/home/riyaz
/home/john
```

This is where documents, downloads, projects, and configuration files are usually stored.

______________________________________________________________________

## /root

Home directory of the **root** user.

```
/root
```

Do not confuse this with `/`.

`/` is the filesystem root.

`/root` is the administrator's home directory.

______________________________________________________________________

## /etc

Contains system configuration files.

Examples

```
/etc/passwd
/etc/hosts
/etc/fstab
/etc/ssh
```

Production servers often require editing files inside `/etc`.

______________________________________________________________________

## /var

Stores variable data.

Examples

- Logs
- Cache
- Databases
- Mail
- Temporary application data

Important directories

```
/var/log
/var/cache
/var/lib
```

______________________________________________________________________

## /usr

Contains installed software.

Examples

```
/usr/bin
/usr/lib
/usr/share
```

Most user applications are installed here.

______________________________________________________________________

## /bin

Essential command-line programs.

Examples

```
ls
cp
mv
cat
pwd
```

Modern Linux distributions often merge `/bin` into `/usr/bin`.

______________________________________________________________________

## /sbin

System administration commands.

Examples

```
fdisk
mount
reboot
shutdown
```

______________________________________________________________________

## /tmp

Temporary files.

Programs frequently store temporary data here.

Files may be deleted automatically after reboot.

______________________________________________________________________

## /boot

Contains files required during system startup.

Examples

- Linux kernel
- Bootloader configuration
- Initial RAM disk

______________________________________________________________________

## /dev

Contains device files.

Examples

```
/dev/sda
/dev/null
/dev/random
/dev/tty
```

Remember:

In Linux, devices appear as files.

______________________________________________________________________

## /proc

A virtual filesystem.

Provides runtime information about:

- Processes
- CPU
- Memory
- Kernel

Example

```
/proc/cpuinfo
/proc/meminfo
```

______________________________________________________________________

## /sys

Contains kernel and hardware information.

Frequently used by system administrators and device management tools.

______________________________________________________________________

## /opt

Optional third-party software.

Example

```
/opt/google
```

______________________________________________________________________

## /media

Automatically mounted removable storage.

Example

USB drives.

______________________________________________________________________

## /mnt

Temporary mount point.

System administrators commonly use it for manually mounted filesystems.

# 6. Absolute vs Relative Paths

## Absolute Path

Starts from `/`.

Example

```bash
/home/riyaz/projects/api
```

Always points to the same location.

______________________________________________________________________

## Relative Path

Starts from your current directory.

Suppose you're in

```bash
/home/riyaz
```

Then

```bash
cd projects
```

is a relative path.

# 9. Inodes

Linux stores file metadata in a structure called an **inode**.

An inode stores:

- Owner
- Group
- Permissions
- File size
- Creation time
- Modification time
- Disk block locations

An inode **does not store the filename**.

The filename is stored separately and points to the inode.

______________________________________________________________________

Display inode numbers

```bash
ls -i
```

Example output

```
45823 notes.txt
45824 app.py
```

# 10. Hard Links vs Soft Links (Introduction)

## Hard Link

Points directly to the same inode.

If the original filename is deleted, the data still exists until all hard links are removed.

______________________________________________________________________

## Soft Link (Symbolic Link)

Points to another file by its path.

If the original file is deleted, the symbolic link becomes broken.

We'll cover both in detail later.

# 11. Mount Points

Linux attaches storage devices into the existing directory tree.

Example

```
SSD

↓

/mnt/data
```

Instead of creating a new drive letter, Linux mounts the device into a directory.

# 15. Common Mistakes

❌ Confusing `/` with `/root`

❌ Using relative paths when absolute paths are required

❌ Editing files inside `/etc` without backups

❌ Forgetting hidden files when troubleshooting

______________________________________________________________________

# 16. Best Practices

- Prefer absolute paths in scripts.
- Keep personal files under `/home`.
- Avoid storing custom applications inside system directories.
- Use `tree` to understand project layouts.
- Learn the Linux filesystem hierarchy instead of memorizing commands blindly.

# Interview Questions

## Q1. Why doesn't Linux use drive letters?

**Answer**

Linux organizes all storage devices into a single directory hierarchy beginning at `/`. Additional storage devices are
mounted into directories rather than assigned separate drive letters.

______________________________________________________________________

## Q2. What is an inode?

**Answer**

An inode is a data structure that stores metadata about a file, including permissions, ownership, timestamps, and disk
block locations. It does not store the filename.

______________________________________________________________________

## Q3. What is the difference between an absolute path and a relative path?

**Answer**

An absolute path starts from the root directory (`/`) and always points to the same location. A relative path is
interpreted from the current working directory.

______________________________________________________________________

## Q4. Why is `/proc` called a virtual filesystem?

**Answer**

Because its contents are generated dynamically by the kernel and represent runtime system information rather than data
stored on disk.

______________________________________________________________________

## Q5. What is the purpose of `/etc`?

**Answer**

`/etc` stores system-wide configuration files used by the operating system and installed services.
