# 1. Introduction

Finding files quickly is one of the most common Linux tasks.

As a Backend Engineer, you'll often need to locate:

- Configuration files
- Log files
- SSL certificates
- Dockerfiles
- Kubernetes manifests
- Python scripts
- Environment files
- System binaries
- Running application logs

Linux provides several tools for searching, each designed for a different purpose.

______________________________________________________________________

# 2. Why File Searching Matters

Imagine you're debugging a production server.

Someone says:

> "Update the nginx configuration."

But no one remembers where it is.

You need to locate it immediately.

Instead of manually browsing hundreds of directories:

```text
/
├── etc
├── usr
├── var
├── opt
├── home
└── ...
```

you can simply use:

```bash
find / -name nginx.conf
```

Within seconds, Linux tells you where it is.

______________________________________________________________________

# 3. Searching Files with `find`

`find` is one of the most powerful Linux commands.

It searches the actual filesystem.

Basic syntax:

```bash
find <path> <condition>
```

Example:

```bash
find . -name app.py
```

Output:

```text
./backend/app.py
```

______________________________________________________________________

## Search from Root

```bash
find / -name nginx.conf
```

______________________________________________________________________

## Search Inside Home Directory

```bash
find /home -name "*.py"
```

______________________________________________________________________

## Case Insensitive Search

```bash
find . -iname "*.jpg"
```

`-iname`

↓

Ignores uppercase and lowercase differences.

______________________________________________________________________

## Search by File Type

Regular files

```bash
find . -type f
```

Directories

```bash
find . -type d
```

Symbolic links

```bash
find . -type l
```

______________________________________________________________________

## Search by Size

Greater than 100 MB

```bash
find . -size +100M
```

Less than 5 KB

```bash
find . -size -5k
```

Exactly 10 MB

```bash
find . -size 10M
```

______________________________________________________________________

## Search by Modification Time

Modified today

```bash
find . -mtime 0
```

Modified within last 7 days

```bash
find . -mtime -7
```

Older than 30 days

```bash
find . -mtime +30
```

______________________________________________________________________

## Search Empty Files

```bash
find . -empty
```

______________________________________________________________________

## Search by Owner

```bash
find . -user riyaz
```

______________________________________________________________________

## Search by Permission

```bash
find . -perm 755
```

______________________________________________________________________

## Execute Commands

Delete all `.pyc`

```bash
find . -name "*.pyc" -delete
```

______________________________________________________________________

Find and remove log files

```bash
find . -name "*.log" -delete
```

⚠️ Always verify the results before using destructive options.

______________________________________________________________________

Run command on results

```bash
find . -name "*.log" -exec ls -lh {} \;
```

Explanation

```
{}

↓

Current file

\;

↓

End of command
```

# 4. Searching Files with `locate`

Unlike `find`,

`locate`

doesn't scan the filesystem.

Instead,

it searches a database.

Result

↓

Much faster.

Example

```bash
locate nginx.conf
```

______________________________________________________________________

## Updating Database

```bash
sudo updatedb
```

Without updating,

recent files may not appear.

______________________________________________________________________

## When to Use

Use

`find`

when accuracy matters.

Use

`locate`

when speed matters.

# 5. Finding Executables

## which

Find executable location.

```bash

```

Output

```text

```

______________________________________________________________________

Another example

```bash

```

## whereis

Shows executable,

source,

manual.

```bash

```

Output

```text

/usr/share/man/man1/python3.1.gz
```

Shows how shell interprets command.


Output


## command -v

```bash

```

Useful inside shell scripts.

# 6. Understanding Symbolic Links

A symbolic link (soft link) is like a shortcut.

Example

```
Original File

↓

Shortcut

↓

Open Original
```

Linux command

```bash
ln -s original.txt shortcut.txt
```

Verify

```bash
ls -l
```

Output

```text
shortcut.txt -> original.txt
```

______________________________________________________________________

Delete original

```bash
rm original.txt
```

Now

```text
shortcut.txt
```

becomes a broken link.

______________________________________________________________________

# 7. Understanding Hard Links

Hard links work differently.

Instead of pointing to the filename,

they point directly to the inode.

Create

```bash
ln original.txt hardlink.txt
```

Now both names reference the same data.

Delete original

```bash
rm original.txt
```

The data still exists because

`hardlink.txt`

points to the same inode.

______________________________________________________________________

# Verify Inodes

```bash
ls -li
```

Example

```
123456 original.txt

123456 hardlink.txt
```

Same inode

↓

Same file.

______________________________________________________________________

# 8. Hard Link vs Soft Link

| Feature | Hard Link | Soft Link |
|----------|-----------|-----------|
| Uses inode | ✅ | ❌ |
| Different filesystem | ❌ | ✅ |
| Works after original deleted | ✅ | ❌ |
| Directory links | Usually No | Yes |
| Looks like shortcut | ❌ | ✅ |

______________________________________________________________________

# When to Use Hard Links

- Backup strategies
- Same filesystem
- Multiple filenames

______________________________________________________________________

# When to Use Soft Links

- Shared configuration
- Executables
- Version switching
- Docker volumes
- Kubernetes configuration

# 9. Understanding Inodes

Every file has:

- inode
- filename

Example

```
Filename

↓

Points to

↓

Inode

↓

Points to

↓

Disk Blocks
```

The inode contains:

- owner
- permissions
- timestamps
- size
- block addresses

The filename is stored separately.

______________________________________________________________________

Display inode

```bash
ls -i
```

Detailed metadata

```bash
stat app.py
```

# 11. Common Mistakes

❌ Running `find /` without sufficient permissions, resulting in many "Permission denied" messages.

______________________________________________________________________

❌ Using `find ... -delete` before verifying the search results.

______________________________________________________________________

❌ Assuming `locate` always has up-to-date information.

______________________________________________________________________

❌ Confusing hard links with symbolic links.

______________________________________________________________________

❌ Deleting the original file while expecting a symbolic link to continue working.

______________________________________________________________________

# 12. Best Practices

- Test `find` commands before adding `-delete`.
- Prefer `locate` for quick searches.
- Use symbolic links for configuration files.
- Learn inode behavior thoroughly.
- Use `which` and `command -v` inside scripts.
- Avoid creating unnecessary hard links.

# Interview Questions

## Q1. What is the difference between `find` and `locate`?

**Answer**

`find` searches the live filesystem in real time and is always accurate but slower. `locate` searches a prebuilt
database, making it much faster, but its results may be outdated until the database is refreshed.

______________________________________________________________________

## Q2. What is a symbolic link?

**Answer**

A symbolic link is a special file that stores the path to another file or directory. It acts like a shortcut. If the
original target is deleted or moved, the symbolic link becomes broken.

______________________________________________________________________

## Q3. What is a hard link?

**Answer**

A hard link is another directory entry pointing to the same inode as the original file. Both names reference the same
underlying data, so deleting one filename does not remove the file until all hard links are deleted.

______________________________________________________________________

## Q4. Can hard links span multiple filesystems?

**Answer**

No. Hard links require the same filesystem because they reference an inode, and inode numbers are only unique within a
single filesystem. Symbolic links can point across different filesystems.

______________________________________________________________________

## Q5. When would you choose a symbolic link over a hard link?

**Answer**

Use a symbolic link when linking directories, linking across filesystems, or creating shortcuts to configuration files
or executables. Symbolic links are more flexible and are commonly used in production systems.
