# Aggregations - Part 2

## Introduction

In Part 1, we learned aggregate functions that summarize an entire result set:

- COUNT()
- SUM()
- AVG()
- MIN()
- MAX()

However, in real-world applications, we usually want summaries **per category** rather than for the whole table.

Examples:

- Total employees in each department
- Average salary by department
- Maximum salary in each city
- Total orders placed by each customer
- Revenue generated by each product

This is where **GROUP BY** and **HAVING** come into play.

These are among the most frequently asked SQL interview topics.

______________________________________________________________________

# GROUP BY

`GROUP BY` groups rows having the same values into a single group.

An aggregate function is then calculated **for each group**.

Example:

```sql
SELECT
    department,
    COUNT(*)
FROM employees
GROUP BY department;
```

Result

| department | count |
| ---------- | ----: |
| HR | 3 |
| IT | 3 |
| Finance | 2 |

Instead of one count for the entire table, SQL returns one count for each department.

______________________________________________________________________

# How GROUP BY Works

Suppose we have:

| Name | Department |
| ------- | ---------- |
| Alice | HR |
| Bob | IT |
| Charlie | IT |
| David | Finance |
| Eva | HR |
| Frank | Finance |
| George | IT |
| Helen | HR |

Internally SQL groups them like this:

```text
HR
------
Alice
Eva
Helen

IT
------
Bob
Charlie
George

Finance
---------
David
Frank
```

Then aggregate functions operate on each group.

______________________________________________________________________

# COUNT() with GROUP BY

```sql
SELECT
    department,
    COUNT(*) AS total_employees
FROM employees
GROUP BY department;
```

______________________________________________________________________

# SUM() with GROUP BY

```sql
SELECT
    department,
    SUM(salary) AS total_salary
FROM employees
GROUP BY department;
```

Result

| department | total_salary |
| ---------- | -----------: |
| HR | 195000 |
| IT | 270000 |
| Finance | 75000 |

Frank's NULL salary is ignored.

______________________________________________________________________

# AVG() with GROUP BY

```sql
SELECT
    department,
    AVG(salary) AS average_salary
FROM employees
GROUP BY department;
```

______________________________________________________________________

# MIN() and MAX()

```sql
SELECT
    department,
    MIN(salary) AS minimum_salary,
    MAX(salary) AS maximum_salary
FROM employees
GROUP BY department;
```

______________________________________________________________________

# Multiple Columns in GROUP BY

SQL allows grouping by multiple columns.

Example

```sql
SELECT
    department,
    city,
    COUNT(*) AS employees
FROM employees
GROUP BY
    department,
    city;
```

Result

| department | city | employees |
| ---------- | --------- | --------: |
| HR | Bangalore | 2 |
| HR | Mumbai | 1 |
| IT | Bangalore | 2 |
| IT | Hyderabad | 1 |
| Finance | Chennai | 2 |

Each unique combination forms a separate group.

______________________________________________________________________

# GROUP BY Rules

A common interview question.

When using `GROUP BY`:

Every selected column must satisfy one of these conditions:

- Included in the GROUP BY clause
- Used inside an aggregate function

Incorrect

```sql
SELECT
    department,
    name,
    COUNT(*)
FROM employees
GROUP BY department;
```

This is invalid because `name` is neither grouped nor aggregated.

Correct

```sql
SELECT
    department,
    COUNT(*)
FROM employees
GROUP BY department;
```

Average salary

# HAVING

`HAVING` filters **groups**.

`WHERE` filters **rows**.

This distinction is one of the most common SQL interview questions.

Example

```sql
SELECT
    department,
    COUNT(*) AS total
FROM employees
GROUP BY department
HAVING COUNT(*) >= 3;
```

Result

| department | total |
| ---------- | ----: |
| HR | 3 |
| IT | 3 |

Finance is excluded because it has only two employees.

______________________________________________________________________

# HAVING with SUM()

```sql
SELECT
    department,
    SUM(salary) AS payroll
FROM employees
GROUP BY department
HAVING SUM(salary) > 200000;
```

Result

| department | payroll |
| ---------- | ------: |
| IT | 270000 |

______________________________________________________________________

# WHERE vs HAVING

This interview question appears very frequently.

## WHERE

Filters rows **before** grouping.

```sql
SELECT
    department,
    COUNT(*)
FROM employees
WHERE salary > 70000
GROUP BY department;
```

Only employees earning more than ₹70,000 are grouped.

______________________________________________________________________

## HAVING

Filters groups **after** aggregation.

```sql
SELECT
    department,
    COUNT(*)
FROM employees
GROUP BY department
HAVING COUNT(*) >= 2;
```

Entire groups are filtered.

______________________________________________________________________

# GROUP BY vs DISTINCT

Another popular interview question.

## DISTINCT

Returns unique values.

```sql
SELECT DISTINCT department
FROM employees;
```

Result

```text
HR
IT
Finance
```

______________________________________________________________________

## GROUP BY

Groups rows and allows aggregate functions.

```sql
SELECT
    department,
    COUNT(*)
FROM employees
GROUP BY department;
```

Rule of thumb:

- `DISTINCT` removes duplicates.
- `GROUP BY` creates groups for aggregation.

# Conditional Aggregation

One of the most useful SQL techniques.

Example:

Count employees earning at least ₹80,000.

```sql
SELECT
COUNT(
    CASE
        WHEN salary >= 80000 THEN 1
    END
) AS high_salary_employees
FROM employees;
```

Another example:

Department-wise high earners.

```sql
SELECT
department,
COUNT(
    CASE
        WHEN salary >= 80000 THEN 1
    END
) AS high_salary_count
FROM employees
GROUP BY department;
```

This technique is heavily used in dashboards and interview questions.

# Aggregations with JOINs

Aggregate functions are commonly combined with joins.

Example

Employees

Departments

Find employees per department.

```sql
SELECT
d.department_name,
COUNT(e.employee_id) AS employee_count
FROM departments d
LEFT JOIN employees e
ON d.department_id = e.department_id
GROUP BY d.department_name;
```

Result

| Department | Employees |
| ----------- | --------: |
| HR | 3 |
| Engineering | 3 |
| Finance | 2 |
| Marketing | 0 |

Notice the use of **LEFT JOIN** so departments without employees are also included.

______________________________________________________________________

# SQLAlchemy Example

```python
stmt = (
    select(
        Department.department_name,
        func.count(Employee.employee_id)
    )
    .outerjoin(
        Employee,
        Department.department_id == Employee.department_id
    )
    .group_by(Department.department_name)
)
```

______________________________________________________________________

# SQLModel Example

```python
statement = (
    select(
        Department.department_name,
        func.count(Employee.employee_id)
    )
    .outerjoin(
        Employee,
        Department.department_id == Employee.department_id
    )
    .group_by(Department.department_name)
)
```

# Logical Query Execution Order

This is an interview favorite.

SQL is written in one order but executed logically as:

```text
FROM

↓

JOIN

↓

ON

↓

WHERE

↓

GROUP BY

↓

HAVING

↓

SELECT

↓

DISTINCT

↓

ORDER BY

↓

LIMIT
```

Understanding this explains why:

- WHERE cannot use aggregate functions.
- HAVING works after GROUP BY.
- GROUP BY occurs before SELECT.

______________________________________________________________________

# Performance Considerations

- Filter early using WHERE whenever possible.
- Index grouping columns when frequently queried.
- Avoid grouping unnecessary columns.
- Aggregate only the data you actually need.
- Large GROUP BY operations may require sorting or hashing internally.

______________________________________________________________________

# Common Mistakes

### Using Aggregate Functions in WHERE

Incorrect

```sql
SELECT *
FROM employees
WHERE COUNT(*) > 2;
```

Correct

```sql
SELECT
department,
COUNT(*)
FROM employees
GROUP BY department
HAVING COUNT(*) > 2;
```

______________________________________________________________________

### Selecting Non-grouped Columns

```sql
SELECT
department,
name,
COUNT(*)
FROM employees
GROUP BY department;
```

Invalid in standard SQL.

______________________________________________________________________

### Confusing DISTINCT with GROUP BY

Remember:

- DISTINCT removes duplicates.
- GROUP BY creates groups.

______________________________________________________________________

# Best Practices

- Always alias aggregate columns.
- Prefer WHERE over HAVING when filtering individual rows.
- Use HAVING only for aggregate conditions.
- Keep GROUP BY columns minimal.
- Understand NULL behavior before aggregating.

# Interview Deep Dive

## Answer

**Question:** What is the difference between WHERE and HAVING?

`WHERE` filters individual rows before grouping occurs. `HAVING` filters groups after aggregate functions have been
computed. Since aggregate values do not exist before grouping, aggregate functions such as `COUNT()`, `SUM()`, or
`AVG()` cannot be used in the `WHERE` clause but can be used in the `HAVING` clause.
