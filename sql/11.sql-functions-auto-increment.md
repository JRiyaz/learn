# SQL Functions & Auto Increment

## Introduction

SQL provides many built-in functions that simplify data manipulation, formatting, calculations, and handling of NULL
values. Every backend developer uses these functions daily.

Similarly, databases provide mechanisms to automatically generate unique IDs for records, eliminating the need to
manually assign primary key values.

In this lecture, you'll learn:

- String Functions
- Numeric Functions
- Date & Time Functions
- NULL Functions
- Type Casting
- Auto Increment Columns
- Sequences
- SERIAL vs IDENTITY
- SQLAlchemy Equivalents
- SQLModel Equivalents

These topics are frequently tested in SQL interviews, especially PostgreSQL-based backend roles.

# What is a SQL Function?

A SQL function accepts one or more inputs and returns a value.

Example

```sql
SELECT UPPER('hello');
```

Result

```text
HELLO
```

Functions can be used in:

- SELECT
- WHERE
- ORDER BY
- GROUP BY
- HAVING
- UPDATE

# String Functions

## UPPER()

Converts text to uppercase.

```sql
SELECT UPPER(name)
FROM employees;
```

______________________________________________________________________

## LOWER()

Converts text to lowercase.

```sql
SELECT LOWER(email)
FROM users;
```

______________________________________________________________________

## LENGTH()

Returns string length.

```sql
SELECT LENGTH('PostgreSQL');
```

Result

```text
10
```

______________________________________________________________________

## CONCAT()

Joins multiple strings.

```sql
SELECT CONCAT(first_name, ' ', last_name)
AS full_name
FROM employees;
```

______________________________________________________________________

## TRIM()

Removes leading and trailing spaces.

```sql
SELECT TRIM('   Alice   ');
```

Result

```text
Alice
```

______________________________________________________________________

## SUBSTRING()

Extracts part of a string.

```sql
SELECT SUBSTRING('PostgreSQL', 1, 10);
```

Result

```text
PostgreSQL
```

Another example

```sql
SELECT SUBSTRING(name, 1, 3)
FROM employees;
```

______________________________________________________________________

## POSITION()

Finds a substring.

```sql
SELECT POSITION('SQL' IN 'PostgreSQL');
```

Result

```text
9
```

______________________________________________________________________

## REPLACE()

Replaces text.

```sql
SELECT REPLACE(
    'Hello World',
    'World',
    'SQL'
);
```

Result

```text
Hello SQL
```

# NULL Functions

## COALESCE()

Returns the first non-NULL value.

```sql
SELECT
COALESCE(phone, 'Not Available')
FROM customers;
```

Example

```sql
SELECT
COALESCE(NULL, NULL, 'SQL');
```

Result

```text
SQL
```

Interview Tip:

`COALESCE()` is one of the most frequently used SQL functions.

______________________________________________________________________

## NULLIF()

Returns NULL if two values are equal.

```sql
SELECT NULLIF(10, 10);
```

Result

```text
NULL
```

Useful for avoiding divide-by-zero errors.

Example

```sql
SELECT
salary /
NULLIF(hours_worked, 0)
FROM employees;
```

# Auto Increment Columns

Primary keys are usually generated automatically.

Instead of

```sql
INSERT INTO employees
(employee_id, name)
VALUES (101, 'Alice');
```

the database generates IDs automatically.

______________________________________________________________________

# SERIAL (PostgreSQL)

```sql
CREATE TABLE employees (

    employee_id SERIAL PRIMARY KEY,

    name VARCHAR(100)
);
```

Insert

```sql
INSERT INTO employees(name)
VALUES ('Alice');
```

Result

```text
employee_id

1
```

Next insert

```text
2
```

Then

```text
3
```

______________________________________________________________________

# BIGSERIAL

Same as SERIAL but uses BIGINT.

```sql
CREATE TABLE orders (

    order_id BIGSERIAL PRIMARY KEY

);
```

Useful for billions of rows.

______________________________________________________________________

# SERIAL Internals

Interview question.

`SERIAL` is **not a real data type**.

Internally PostgreSQL creates:

- INTEGER column
- Sequence
- DEFAULT nextval(...)

Equivalent to

```sql
CREATE SEQUENCE employees_employee_id_seq;

CREATE TABLE employees (

    employee_id INTEGER
    DEFAULT nextval(
        'employees_employee_id_seq'
    )
);
```

______________________________________________________________________

# IDENTITY Columns (Recommended)

Modern PostgreSQL recommends `IDENTITY`.

```sql
CREATE TABLE employees (

    employee_id
    INTEGER
    GENERATED ALWAYS AS IDENTITY,

    name TEXT
);
```

______________________________________________________________________

Alternative

```sql
GENERATED BY DEFAULT AS IDENTITY
```

Difference

### ALWAYS

Database always generates values.

Manual insertion is rejected unless explicitly overridden.

______________________________________________________________________

### BY DEFAULT

Database generates values when none are supplied.

Manual values are also allowed.

______________________________________________________________________

# SERIAL vs IDENTITY

| SERIAL | IDENTITY |
| ---------------------------- | ------------------------------------------- |
| Legacy PostgreSQL feature | SQL Standard |
| Creates an implicit sequence | Managed by the database |
| Harder to modify | Easier to manage |
| Still widely used | Recommended for new PostgreSQL applications |

**Recommendation:** Prefer `GENERATED ... AS IDENTITY` for new PostgreSQL projects.

# Sequences

A sequence generates unique numbers.

Create

```sql
CREATE SEQUENCE employee_seq;
```

Next value

```sql
SELECT nextval('employee_seq');
```

Current value

```sql
SELECT currval('employee_seq');
```

Restart

```sql
ALTER SEQUENCE employee_seq
RESTART WITH 1;
```

# SQLAlchemy Auto Increment

```python
from sqlalchemy import Column
from sqlalchemy import Integer
from sqlalchemy import String

class Employee(Base):

    __tablename__ = "employees"

    employee_id = Column(
        Integer,
        primary_key=True
    )

    name = Column(String)
```

For integer primary keys, SQLAlchemy automatically uses the database's native auto-increment mechanism where supported.

______________________________________________________________________

# SQLModel Auto Increment

```python
from sqlmodel import SQLModel
from sqlmodel import Field

class Employee(SQLModel, table=True):

    employee_id: int | None = Field(
        default=None,
        primary_key=True
    )

    name: str
```

The database generates the ID during insertion.

# Common Mistakes

### Using SERIAL in New PostgreSQL Projects

Prefer `IDENTITY`.

______________________________________________________________________

### Using COALESCE Incorrectly

Remember:

```sql
COALESCE(
NULL,
'A',
'B'
)
```

returns

```text
A
```

______________________________________________________________________

### Confusing CAST with CONVERT

`CAST` is ANSI SQL.

`CONVERT` exists in some databases (such as SQL Server) but is not standard SQL.

______________________________________________________________________

### Manually Managing Primary Keys

Avoid generating numeric IDs in application code when the database provides auto-increment or sequences.

______________________________________________________________________

# Best Practices

- Prefer `IDENTITY` over `SERIAL` for new PostgreSQL applications.
- Use `COALESCE()` for NULL handling.
- Use `NULLIF()` to avoid divide-by-zero.
- Use `CAST()` for portability.
- Keep date calculations inside the database when appropriate.
- Choose `BIGSERIAL` or `BIGINT IDENTITY` for very large tables.

# Interview Deep Dive

## Answer

**Question:** What is the difference between `SERIAL` and `IDENTITY` in PostgreSQL?

`SERIAL` is a PostgreSQL-specific convenience feature that creates an integer column, an associated sequence, and a
default expression using `nextval()`. `IDENTITY` is part of the SQL standard and is the recommended approach for modern
PostgreSQL applications. It provides better integration with the database engine and clearer ownership of the underlying
sequence.
