# Database Scaling Masterclass

## Why This Module?

So far, we've used a single PostgreSQL database.

```text
FastAPI
    │
    ▼
PostgreSQL
```

This works well until your application starts receiving millions of requests.

Questions naturally arise:

- What happens when one database server is full?
- How do companies like Amazon or Uber scale?
- How does the application know which database to query?
- How do we write Python code that supports multiple databases?
- What are read replicas?
- What is sharding?
- How do transactions work across shards?
- How do ORMs handle multiple databases?

This module answers those questions.

## Why Learn This Before Docker?

Once we understand database scaling, Docker becomes much more meaningful because we'll containerize:

- Primary database
- Read replica
- Sharded databases
- Redis
- Kafka

instead of only a single PostgreSQL instance.

By the time we reach the final microservices project, you'll already understand not only **how** to deploy multiple
databases, but **why** the architecture is designed that way.
